# Agent Ops — แจกงานให้ AI ตัวอื่น, เลือกรุ่น, ประหยัด token

> แนวคิดการใช้ agent อย่างคุ้ม token เฉพาะส่วนที่ไม่ขัดกับ Mentor Mode
> AI อ่านไฟล์นี้ **เฉพาะตอนจะแจกงานให้ subagent, งานไม่ผ่านการตรวจในโหมดด่วน หรือเมื่อ token ใกล้หมด** ไม่ต้องอ่านทุก session

## 1. ประหยัด token (ใช้เสมอ)

- ตัด output ก่อนเข้าแชต: ใช้ `tail`, `head`, `--stat`, แสดงเฉพาะบรรทัดที่ fail log ยาวให้เขียนลงไฟล์ชั่วคราวแล้ว `grep`
- อ่านไฟล์เป็นช่วงบรรทัด ไม่อ่านทั้งไฟล์ถ้าไม่จำเป็น และไม่อ่านซ้ำสิ่งที่อยู่ในบทสนทนาแล้ว
- ใช้ข้อความหน้าเว็บ / accessibility tree แทน screenshot ถ้าต้องใช้ภาพให้ลดขนาดราวครึ่งหนึ่ง
- บทสนทนายาวมากแล้ว และงานถัดไปไม่เกี่ยวกัน ให้แนะนำผู้ใช้เปิด session ใหม่ (สถานะอยู่ใน `status.md` อยู่แล้ว)

## 2. เลือกรุ่นตามงาน (Claude Code subagent)

| ระดับ | รุ่น | ใช้กับ |
|---|---|---|
| เร็ว | Haiku | หาข้อมูล: ไฟล์ X มีไหม, อ่าน log, grep, ค้นหลายไฟล์แบบอ่านอย่างเดียว |
| มาตรฐาน | Sonnet | ผลลัพธ์เป็นการตัดสินหรือโค้ด: ตรวจผ่าน/ไม่ผ่าน, วิเคราะห์, เขียนโค้ดตาม spec ชัด |
| แรง | Opus | session หลักที่คุยกับผู้ใช้ และงานที่ยังไม่ชัดว่าต้องทำอะไร |

- กำหนดรุ่นของ subagent ทุกครั้ง ห้ามปล่อยให้ใช้รุ่นแพงตามตัวหลักโดยไม่ตั้งใจ
- รุ่นเร็วอาจอ่านรายละเอียดเล็กพลาด (เช่น `*` สีแดง) ให้สั่งตรวจซ้ำก่อนรายงานว่า "ไม่มี"
- effort เริ่มที่ medium (งานอ่านอย่างเดียวใช้ low) เพิ่มเมื่อเห็นว่าจำเป็นเท่านั้น
- ไม่เกิน 2 subagent พร้อมกัน และ subagent ห้ามแจกงานต่อ

## 3. เมื่อแจกงานให้ subagent (brief)

subagent ไม่เห็นบทสนทนา brief คือข้อมูลทั้งหมดที่มันมี
- **เป้าหมาย:** ไฟล์หรือส่วนที่รับผิดชอบ และอ่านอย่างเดียวหรือแก้ได้
- **ข้อห้าม:** ห้าม commit/push, อยู่ใน repo ที่ได้รับอนุญาต, ห้ามแตะ secret และ `.env`
- **ให้ข้อมูลที่รู้แล้วไปเลย:** path, branch, สัญญา API (field, message) จะได้ไม่ต้องค้นใหม่
- **รายงานกลับ:** ไฟล์ที่เปลี่ยน, ผลคำสั่งตรวจจริง, สิ่งที่ยังไม่ได้ยืนยัน
- **ห้ามเดา business rule / API contract** ให้ถามกลับผ่าน session หลัก

## 4. Escalation ladder — เมื่องานที่ AI ทำไม่ผ่านการตรวจ

ไต่ทีละขั้น ห้ามกระโดดไปรุ่นแพงทันที

1. **ส่งกลับให้ตรวจตัวเอง** บอกให้ชัดว่าข้อไหนไม่ผ่าน ให้เทียบกับแผนและ pattern เดิมใน repo (รุ่นและ effort เดิม)
2. **เพิ่ม effort 1 ระดับ** (low → medium → high)
3. **ขึ้นรุ่น 1 ระดับ** แล้วเริ่ม effort ต่ำใหม่ (Claude: Haiku → Sonnet → Opus · Antigravity: Flash → Pro)
4. **รุ่นสูงสุด หรือ effort สูงสุด ต้องขอผู้ใช้ก่อน**

- ถ้าทำเองไม่มี subagent (เช่น Antigravity) ให้ใช้ข้อ 1-2 กับตัวเอง แล้วข้อ 3-4 ให้แนะนำผู้ใช้เปลี่ยนรุ่นแทน
- จดใน `<project>/log.md` ว่าขั้นไหนแก้ได้ เช่น `ladder: ขั้น 2 (เพิ่ม effort) ผ่าน` นานไปจะรู้ว่าค่าเริ่มต้นควรปรับไหม

## 5. ข้อที่ไม่เอามา (ขัดกับ Mentor Mode)

- "งานแก้โค้ดส่ง worker ทันทีโดยไม่ถาม" → ใน repo งาน ผู้ใช้เขียนเองเป็นค่าเริ่มต้น แจกงานได้เฉพาะงานค้นหา/อ่าน หรือเมื่อผู้ใช้สั่ง implement
- auto commit / MR / ย้ายการ์ด → ผู้ใช้ทำเอง หรือสั่งเป็นครั้งๆ
