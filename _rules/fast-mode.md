# โหมดด่วน (Fast Mode) — วางแผนให้เห็นก่อน แล้วแจก worker ทำให้จนจบ

> อ่านไฟล์นี้คู่กับ `_rules/agent-ops.md` เสมอเมื่อผู้ใช้เปิดโหมดด่วน ใช้ได้ทั้ง Claude Code และ Antigravity
> ค่าเริ่มต้นของทุก session คือ **โหมดเรียน** (Mentor Mode: ผู้ใช้เขียนเอง AI สอนและตรวจ)

## เปิด / ปิด

- **เปิด:** ผู้ใช้พิมพ์ "โหมดด่วน" หรือ "ช่วยผมด้วย ผมไม่ไหวแล้ว"
- **ปิด:** ผู้ใช้พิมพ์ "กลับโหมดเรียน" หรือเปิด session ใหม่ (ยกเว้น `handoff.md` ระบุว่า `โหมด: ด่วน`)
- ตอบรับทุกครั้งที่สลับ 1 บรรทัด: `**โหมดด่วน** · AI วางแผนและแจกงานให้ worker จนจบ คุณ commit / push / MR เอง`

---

## ⛔ Hard Gate — ห้ามข้ามขั้นสรุปแผนเด็ดขาด

- **แม้ผู้ใช้จะพิมพ์คำสั่งงานมาพร้อมคำว่า "โหมดด่วน" ก็ห้ามแก้ไฟล์หรือสั่ง worker แก้โค้ดทันที**
- ทำได้แค่อ่านไฟล์ / สำรวจบริบทที่จำเป็น (ใช้ fast worker ถ้าต้องค้นกว้าง)
- จากนั้น **ต้องหยุดและส่งแม่แบบ "สรุปก่อนลุย"** ให้ผู้ใช้เห็นก่อนเสมอ แล้วรอผู้ใช้ตอบ **"ลุย"** (หรือปรับแผน) จึงค่อยลงมือทำ

### แม่แบบ "สรุปก่อนลุย" (บังคับใช้ก่อนแก้ไฟล์ทุกครั้ง)

````markdown
**โหมดด่วน** · AI วางแผนและแจกงานให้ worker จนจบ คุณ commit / push / MR เอง

### 🎯 ผลลัพธ์ที่จะได้
- (จะเห็นอะไร / พฤติกรรมที่เปลี่ยน / เงื่อนไขที่ต้องผ่าน)

### 📋 แผนงาน
- [ ] 1. ...
- [ ] 2. ...
- [ ] 3. ตรวจตัวเอง + รัน typecheck / lint / test

### 🤖 แผนแจกงานและรุ่น (Model Routing)
- **ตัวหลัก (Coordinator):** วางแผน, ตรวจ diff, สรุปผล
- **Worker ค้นหา (fast — Haiku / flash_lite):** (ระบุงาน หรือ "ไม่ต้องใช้เพราะงานเล็ก")
- **Worker ลงมือทำ (standard — Sonnet / flash หรือ pro):** (ระบุไฟล์/ส่วนที่ทำ)

---

### ➡️ NEXT ACTION
ตรวจสอบแผนด้านบน ถ้าตรงตามที่ต้องการพิมพ์ **"ลุย"** เพื่อเริ่มทำ (หรือบอกจุดที่อยากปรับก่อน)
````

## ลำดับงาน

```
☐ 1. อ่านโจทย์ / การ์ดที่ผู้ใช้วางมา + status.md + core/rules.md ของโปรเจกต์ + _rules/agent-ops.md
☐ 2. ส่งแม่แบบ "สรุปก่อนลุย" (ผลลัพธ์ + แผน + แผนรุ่น worker) → ⛔ หยุดรอผู้ใช้ตอบ "ลุย"
☐ 3. หลังผู้ใช้ตอบ "ลุย" → ลงมือทำทุกขั้นต่อกันโดยใช้ worker ตามแผน
☐ 4. ตัวหลักตรวจ diff (--stat) + ผลคำสั่ง typecheck / lint / test / e2e จริง
☐ 5. สรุป: ไฟล์ที่แก้ (--stat), ผลคำสั่งตรวจจริง, รุ่น worker ที่ใช้จริง, สิ่งที่ยังไม่ได้ยืนยัน, ข้อความ commit พร้อมก๊อป
☐ 6. ผู้ใช้ commit / push / เปิด MR / ย้ายการ์ดเอง
☐ 7. อัปเดต status.md + log.md + "3 อย่างที่ควรกลับมาเรียนทีหลัง"
```

- ระหว่างข้อ 3 รายงานความคืบหน้าสั้นๆ ด้วย checklist `- [ ]` / `- [x]` ตาม `_rules/response-format.md` ไม่ต้องแสดง Before/After ทุกจุด
- ตรวจในข้อ 4 ไม่ผ่าน → แก้ตาม **Escalation ladder** ใน `_rules/agent-ops.md` หัวข้อ 4 (ตรวจตัวเอง → เพิ่ม effort → ขึ้นรุ่น → รุ่นสูงสุดต้องขอก่อน)
- ผู้ใช้ทดสอบแล้วพิมพ์ "Feedback: ..." → ทำตาม `_rules/response-format.md` แม่แบบ 5 (โหมดด่วนแก้ให้เลยแล้วรันตรวจ)
- ติดเรื่อง business rule, API contract หรือข้อมูลที่ไม่แน่ใจ **ให้หยุดถาม ห้ามเดา** แม้จะรีบ

## Standing Order — บังคับแตกงานและสลับรุ่นในโหมดด่วน

> นำแนวคิดการแยก Coordinator + Worker มาใช้เต็มรูปแบบเฉพาะตอนอยู่ในโหมดด่วน (ไม่ขัด Mentor Mode)

- **ตัวหลัก (Coordinator / รุ่นแรง)** ทำหน้าที่:
  - คุยกับผู้ใช้, วางแผน, ตัดสินใจ, ถามเมื่อติด business rule
  - เขียน brief ให้ worker, ตรวจ diff (`git diff --stat`) และผลรันของ worker, สรุปจบงาน
- **บังคับโยนงานไป worker (ไม่ทำเองในตัวหลัก)** เมื่อ:
  - ค้นหาหลายไฟล์ / อ่าน log ยาว / สำรวจโค้ดกว้าง → โยนให้ **fast worker** (Claude: `haiku` · Antigravity: `flash_lite` / `flash`)
  - แก้โค้ดหลายไฟล์ / ทำฟีเจอร์ตาม spec / รันเทสต์ → โยนให้ **standard worker** (Claude: `sonnet` · Antigravity: `flash` / `pro`)
  - *ข้อยกเว้น:* งานเล็กมาก (แก้ 1 จุด หรือไม่เกิน ~3 tool calls) ทำในตัวหลักได้เลย ไม่ต้องแตก worker
- **กำหนดรุ่นทุกครั้ง:** ห้ามปล่อย worker สืบทอดรุ่นแพงจากตัวหลักโดยไม่ตั้งใจ (ดูตารางรุ่นใน `_rules/agent-ops.md`)
- **ประกาศก่อนเรียก worker เสมอ (Announce):** พิมพ์ 1 บรรทัดบอกผู้ใช้ก่อนเรียก เช่น `🤖 เรียก worker [ชื่อ/บทบาท] (รุ่น: Sonnet / flash) — แก้ไฟล์ ...`
- **จำกัดจำนวน:** ไม่เกิน 2 worker พร้อมกัน · สองตัวห้ามแก้ไฟล์เดียวกันพร้อมกัน · worker ห้ามแตก worker ต่อ
- **ห้ามโกหก:** ห้ามบอกว่าเรียก worker หรือใช้รุ่นอื่นถ้าไม่ได้เรียกจาก tool จริง

---

## ห้ามแม้อยู่ในโหมดด่วน

- แก้ไฟล์หรือสั่ง worker แก้โค้ดก่อนผู้ใช้ตอบ **"ลุย"**
- push, เปิด MR/PR, merge, deploy เอง — ยกเว้นผู้ใช้สั่งในข้อความนั้นชัดๆ
- แก้ไฟล์ที่ทีมใช้ร่วมกัน (config กลาง, CI, lock file ที่ไม่เกี่ยว) โดยไม่บอกก่อน
- แตะ secret, `.env`, ข้อมูลจริงของผู้ใช้ระบบ
- บอกว่า "เสร็จ/ผ่าน" โดยไม่มีผลคำสั่งตรวจจริง

## สรุปตอนจบ (รูปแบบ)

````markdown
### 🎉 งานเสร็จ (โหมดด่วน) · 4/4
- [x] 1. ...

**ไฟล์ที่แก้:** `src/a.ts`, `src/b.vue` (+120 −15)
**Worker ที่ใช้:** ค้นหา (`haiku`/`flash_lite`) · แก้โค้ด (`sonnet`/`flash`)
**ตรวจแล้ว:** `npm run typecheck` ผ่าน · `npm test` ผ่าน 24/24
**ยังไม่ได้ยืนยัน:** ทดสอบบน staging

**ข้อความ commit**
```text
feat(users): เพิ่มปุ่ม export ผู้ใช้เป็น Excel
```

### 🎓 กลับมาเรียนทีหลัง
1) streaming response 2) xlsx library 3) การจำกัดจำนวนแถว

---

### ➡️ NEXT ACTION
commit / push / เปิด MR แล้วย้ายการ์ด · พิมพ์ **"กลับโหมดเรียน"** เมื่อเสร็จงานด่วน
````

## ส่งไม้ต่อ (handoff)

- ถ้าส่งไม้กลางงานด่วน ให้เขียน `โหมด: ด่วน` ใน `handoff.md` ผู้รับไม้ (Claude Code หรือ Antigravity) จะทำต่อในโหมดด่วนทันที (และถ้ายังไม่เคยอนุมัติแผน ก็ต้องส่ง "สรุปก่อนลุย" ก่อน)
